# Order! MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the MVP of "Order! A Board Meeting Simulator" — Level 1 (Willow Creek HOA fence variance), palette input, turn-based, deterministic engine, two meters, collapse/checkpoint restart, report card — deployed to GitHub Pages.

**Architecture:** A pure-TypeScript deterministic rules engine in `/src/engine` (zero React imports, seeded PRNG, reducer-shaped, fully unit tested, runnable from Node). Static JSON scenarios in `/src/content`. A React UI in `/src/ui` that is a thin renderer over the engine reducer. Modes in `/src/modes` only filter what the palette shows.

**Tech Stack:** Vite 7 + React 19 + TypeScript (strict), Vitest for tests, `tsx` for the Node CLI, GitHub Actions → GitHub Pages.

**Spec:** `docs/spec.md` (read it before starting any task).

## Global Constraints

- Engine files must have **zero React imports** and no browser globals; `npx tsx scripts/play.ts` must run the whole game headless.
- **No LLM/API calls at runtime.** Content is static JSON.
- **Determinism:** same scenario + same seed + same action sequence ⇒ identical state and log. No `Date.now()`, no `Math.random()` in the engine — use the seeded RNG in state.
- No "Correct!"/"Wrong!" feedback during play. Consequences only. Post-meeting report card is the only grading surface.
- In Practice mode the palette shows OUT_OF_ORDER actions as clickable. Only Learn mode filters to IN_ORDER.
- All rule/help text is **original paraphrase** — never text from RONR 12th ed.
- SEMVER: MVP completes as tag `v0.1.0`. Conventional commits (`feat:`, `test:`, `chore:`…), commit after every green task step.
- Vite `base: '/bms/'` for GitHub Pages at `https://polarispixels.github.io/bms/`.
- TypeScript `strict: true`. Engine has no runtime dependencies.

### D1. Engine public API (`src/engine/index.ts`)

```ts
export function initMeeting(scenario: Scenario, seed: number): MeetingState;
export function reduce(state: MeetingState, action: Action, scenario: Scenario): MeetingState;
export function legalActions(state: MeetingState, scenario: Scenario): LegalityReport;

```

`reduce` is pure: it never mutates its input; new events append to `state.log`. `reduce` on a `COLLAPSED` or `ADJOURNED` state returns state unchanged except a NARRATION event ("The meeting is over.").

### D3. Legality matrix (verb × phase)

O = OUT_OF_ORDER, I = IN_ORDER, R = RISKY. Overrides listed below the table win.

| verb | PRE_MEETING | ITEM_OPEN | MOTION_PENDING | DEBATE | VOTING | RECESS | ADJOURNED/COLLAPSED |
|---|---|---|---|---|---|---|---|
| CALL_ITEM | I (call to order + first item) | I if current item resolved, else O | O | O | O | I (resume) | O |
| RECOGNIZE | O | I | I | I | O | O | O |
| STATE_MOTION | O | O | I (unstated motion on stack) | O (already stated → R "restating") | O | O | O |
| RULE | I if pending point, else O | same | same | same | same | same | O |
| ANSWER_INQUIRY | I if pending inquiry, else O | same | same | same | same | same | O |
| CALL_VOTE | O | O | O (unstated/unseconded) | I; R if pending RECOGNITION requests (cutting off debate) | O (already voting) | O | O |
| ANNOUNCE_RESULT | O | O | O | O | I | O | O |
| GAVEL | I if pending INTERRUPT, else R ("gaveling a quiet room") | same | same | same | same | O | O |
| RECESS | R | R | R | R | O | O | O |
| ADJOURN | R (nothing done) | I if all items completed, else R (business remains) | O | O | O | O | O |
| WAIT | I | I | I | I | I | I | O |

Overrides:
- No quorum (`quorumPresent === false`): everything O except WAIT, RECESS(R), ADJOURN(I), GAVEL(R). Level 1 always has quorum, but implement the rule.
- CALL_VOTE in DEBATE when motion `statedByChair === false`: O (this is the "misstated/never-stated motion" trap that triggers the Rules Enthusiast).
- RULE on a request whose `valid === true` with `NOT_WELL_TAKEN` is legal but costs trust (see D5) — legality stays I; the *palette* never previews that cost.

Taking an O action does not throw. The engine applies consequences (D5) and emits confused/objection events instead of the intended effect.

### D4. Turn loop

`reduce` = (1) apply chair action (or consequence if out of order) → (2) `roomRespond` (beats fire, archetypes react, at most one NPC "scene" per turn to keep pacing readable) → (3) meter decay/passive effects (unaddressed interrupts drain) → (4) collapse check → (5) checkpoint capture if entering a checkpoint boundary → (6) `turn++`.

`WAIT` skips (1). NPC ordering is deterministic: beats first (scenario order), then archetypes in member-array order.

### D5. Meter deltas (exact values, `src/engine/meters.ts`)

Meters start at 70, clamp 0–100. Every change goes through `applyDelta(state, meter, reasonKey)` and appends to `meterLog`.

| reason key | meter | Δ | fires when |
|---|---|---|---|
| OUT_OF_ORDER_ACTION | control | −6 | chair takes an O action |
| UNADDRESSED_INTERRUPT | control | −8 | per turn an INTERRUPT request sits unaddressed |
| HESITATION | control | −3 | WAIT while any pendingRequests exist |
| STABILIZER_RESCUE | control | −4 | stabilizer fixes the chair's mess |
| GAVEL_RESTORES_ORDER | control | +8 | GAVEL with pending INTERRUPT (clears them) |
| GAVEL_QUIET_ROOM | trust | −4 | GAVEL with no disorder |
| CLEAN_PROCEDURE_BONUS | control | +3 | motion stated correctly; result announced within 1 turn of vote |
| CUT_OFF_DEBATE | trust | −6 | CALL_VOTE while RECOGNITION requests pending |
| INVALID_RULING | trust | −10 | RULE NOT_WELL_TAKEN on a `valid: true` point |
| TECHNICALITY_RULING | trust | −5 | RULE WELL_TAKEN on a `valid: false` point *against* a member (siding with a bogus objection) |
| CORRECT_RULING | control | +4 | ruling matches `valid` |
| SELECTIVE_RECOGNITION | trust | −5 | recognizing a member while another has waited ≥2 turns longer |
| WRONG_INQUIRY_ANSWER | control | −4 | ANSWER_INQUIRY with `correct: false` answer |
| IGNORED_REQUEST_TIMEOUT | trust | −4 | any request unaddressed for 3 turns (fires once per request) |
| RECESS_BREATHER | control | +5 | RECESS taken with control < 40 (also resets all impatience to 0) |
| RECESS_STALL | trust | −3 | RECESS taken with control ≥ 40 |
| PREMATURE_ADJOURN | trust | −8 | ADJOURN with agenda business remaining (meeting still ends) |

Collapse: after every reduce, if `control <= 0` → phase `COLLAPSED`, emit 3 NARRATION/INTERRUPT chaos events (room talks over chair, motion dies, gavel ignored).

### D6. Archetype rules (`src/engine/room.ts`)

Deterministic, driven by state — no randomness in *whether* they fire, only seeded RNG for *which line* of authored dialogue renders.

- **RULES_ENTHUSIAST** — When the chair takes an O action, or CALL_VOTE on an unstated motion: files `POINT_OF_ORDER` with `valid: true` next roomRespond. At most one pending point from them at a time.
- **VETERAN** — First time DEBATE opens on an agenda item flagged `veteranBait: true`: files RECOGNITION with `purpose: 'COMMENT'`. If recognized: burns the turn with the 2019 story (efficiency cost only — turn passes). If still pending when 2 other members have been recognized since: `IGNORED_REQUEST_TIMEOUT` applies (trust −4) and they withdraw.
- **INTERRUPTER** — `impatience` +1 each turn there is any pending request or the chair WAITs; +2 if the chair WAITs with them pending. At impatience ≥ 3: emits INTERRUPT event + INTERRUPT request, resets to 0. Interrupt is cleared by GAVEL (+control) or RECOGNIZE (legitimizes: interrupt converts to the floor, no control recovery).
- **STABILIZER** — If `consecutiveWaits >= 2`, or a moved motion sits unseconded for 2 turns, or an unstated motion sits for 3 turns: performs the correct fix (seconds it / prompts "Madam Chair, I believe the motion needs to be stated") as a SPEECH event, applies STABILIZER_RESCUE (−4 control), fixes state (e.g. sets `seconded`).
- **DRIFTING_COMMENTER** — When recognized for debate: speech runs 2 turns instead of 1 (second turn auto-continues unless chair GAVELs; GAVEL here = trust −4 via GAVEL_QUIET_ROOM path relabeled `CUT_OFF_RAMBLER`, add that key: trust −4). Letting it run costs the extra turn (efficiency).

Add meter key: `CUT_OFF_RAMBLER | trust | −4 | gavel during a drifting speech`.

### D9. Report card (`src/engine/report.ts`)

```ts
export type ReportCard = {
  grades: Record<'procedure' | 'fairness' | 'efficiency' | 'clarity' | 'completion', { grade: 'A'|'B'|'C'|'D'|'F'; score: number; notes: string[] }>;
  overall: 'A'|'B'|'C'|'D'|'F';
  meterFinal: { control: number; trust: number };
  pedantry: string[];   // 3–6 pedantic observations pulled from meterLog reasons
};
```

Scoring (0–100 → A≥90, B≥80, C≥70, D≥60, F<60):
- procedure: 100 − 12·outOfOrderCount − 8·(invalid rulings)
- fairness: trust final, minus 5 per SELECTIVE_RECOGNITION occurrence
- efficiency: 100 − 4·max(0, turns − parTurns)
- clarity: 100 − 10·(motions that entered DEBATE unstated) − 5·(announce delays > 1 turn)
- completion: 100·itemsCompleted/agenda.length
- overall: mean of the five, letter-graded.
Notes/pedantry lines are original prose generated from reason keys (a static map, no LLM).

### D10. Checkpoints

Captured automatically in `reduce` when: (a) phase transitions into ITEM_OPEN for a new item, (b) immediately before applying CALL_VOTE. Snapshot stores state with `checkpoints: []` and `log` truncated to last 20 events (memory hygiene). `restoreCheckpoint(collapsedState)` returns the latest checkpoint's state (with rngState advanced by 1 so retries aren't verbatim) and a diagnostic: the 3 largest-magnitude negative `MeterDelta`s from `meterLog` since that checkpoint's turn.

### Task 5: Reducer core (chair actions, phases, votes)

**Files:** Create `src/engine/reducer.ts`, `src/engine/render.ts`; tests `reducer.test.ts`.

**Interfaces (produces):** `initMeeting`, `reduce`, `latestEvents` (D1); `renderEvent(e: MeetingEvent, scenario: Scenario, rngState: number): { line: string; rngState: number }`.

**Behavior to implement (chair half of D4 only — roomRespond is Task 6, stub it as identity):**
- initMeeting: PRE_MEETING, quorum from `present.length >= quorum`, meters 70/70, NARRATION events for call-to-order setting.
- CALL_ITEM: PRE_MEETING→ITEM_OPEN item 0, or advance to next item when resolved; emits STATE_CHANGE + CLERK narration.
- RECOGNIZE pending RECOGNITION: floorHolder set; the request's purpose executes (MOVE → motion pushed unstated+unseconded, phase MOTION_PENDING; DEBATE_FOR/AGAINST/COMMENT → SPEECH event, `debateSpeeches++`, floor returns). RECOGNIZE an INTERRUPT: legitimizes (converts to floor, clears request). RECOGNIZE with no request: SPEECH "member demurs" + nothing.
- STATE_MOTION: top motion `statedByChair = true`, phase DEBATE (requires seconded; if unseconded it is O per D3 via MOTION_PENDING rules — clarify: STATE_MOTION is I in MOTION_PENDING only when top motion is seconded; add that override to legality tests in this task).
- CALL_VOTE (I case): tally from `motion.votes` of present members, phase VOTING, `currentVote` set, CLERK narration of the voice vote.
- ANNOUNCE_RESULT: pop motion, VOTE_RESULT event, `currentVote.announced = true`; stack empty → item resolved (`itemsCompleted++`), phase ITEM_OPEN; CLEAN_PROCEDURE_BONUS if within 1 turn.
- RULE / ANSWER_INQUIRY: resolve request, apply D5 deltas (CORRECT_RULING / INVALID_RULING / TECHNICALITY_RULING / WRONG_INQUIRY_ANSWER).
- GAVEL / RECESS / ADJOURN / WAIT: per D3+D5. RECESS: phase RECESS, next CALL_ITEM resumes prior phase context (MVP: returns to ITEM_OPEN of current item; motion stack preserved).
- Out-of-order chair action: OUT_OF_ORDER_ACTION delta, `outOfOrderCount++`, intended effect does NOT happen, emit SPEECH confusion event (intent `CONFUSION`).
- Collapse check + checkpoint capture (D10) inline in reduce.
